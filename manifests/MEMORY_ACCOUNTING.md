# Memory Accounting Definitions

Do not merge component fields into a universal total unless the same allocation boundary is serialized for every method. The release distinguishes retained real examples, retained feature bytes, labels, stored logits, classifier state, generator state, critic/discriminator state, snapshots, optimizer state, temporary generated batches, peak GPU allocation, and checkpoint/disk footprint.

The standard K-matched protocol uses AHR/ER/DER++ K=100 on EMBER and K=200 on AZ-Class. The separate **approximately implementation-tracked-memory-matched setting** uses AHR/ER/DER++ K=100/600/550 on EMBER and K=200/900/875 on AZ-Class. It supports retained-historical-real-data trade-off statements only; it is not equal-real-data, exact-total-memory, or universally memory-matched.
